# 素材スタジオ：画像ごとのコメント機能の設計

2026-11-03 作成（Claude・Opus 5.5）、同日社長承認・Codex実装。状態：**本番反映済み（2026-11-03）**。依頼書とスタッフ案内文案は AI_Workspace の `docs/codex-request-sozai-image-comments-20261103.md`。

## 依頼

日本カラクリ経済学のSayumiさんから（Chatwork 11/3）。新居先生の「出先やスキマ時間にスマホで確認したい」という意見を受けて：

- 途中の確認では、**ツールの中で画像ごとにコメント**し、コメントを見ながらやり直したい。
- 全画像が完成したら、従来どおり**スプシに書き出して編集者さんに共有**したい（せいまさん依頼で10/23に入れた機能）。
- まず、三上さんが今作っている画像に、みんなでコメントしていきたい。

社長の返事は「途中のやりとりをしやすくする、ということですね。改修してみますね」。

## 今の作り（2026-11-03 時点）

| 項目 | 今 |
|---|---|
| 場面へのメモ | 「要修正メモ」が場面ごとに1件だけ（`material_library.json` の `flags`・最大500字）。書いた人・日時は残らず、上書きされる。書き出しを止める印を兼ねる |
| スプシ書き出し | 全場面・画像プレビュー付き。黄色の「コメント」列は**空欄で出力**。シート上のコメントはツールへ取り込まない |
| ログイン | Cloudflare Access（メールのコード）。サーバーは証明から**本人のメール**を確かめられる（`cloudflare_access.verified_email`）が、今は使っていない |
| スマホ | 素材画面・比較ダイアログは390px幅で確認済み。候補は横スクロール |
| 保存 | Render の `/data`（1 worker・プロセス内のロック）。案件ごとに `output/<job>/` |

## 方針

1. **コメントは「要修正メモ」と別に作る**。要修正メモは「書き出しを止める印」のまま残し、コメントは誰でも何件でも書ける会話にする。役割を混ぜない。
2. **コメントは画像（候補）に付ける**。場面だけに付けると、作り直した後に「どの画像への指摘か」が分からなくなるため。作り直した後も、前の画像へのコメントは「前の候補へのコメント」として小さな画像付きで残る。
3. **「対応済み」で閉じる**。作り手が直したら「対応済み」にする。書いた人・ほかの人は「もう一度開く」ができる。消さずに履歴として残る。
4. **スマホで1本指で回せる**ことを最優先にする（新居先生の使い方）。
5. **書き出しは今のスプシに列を足すだけ**。コメント列の空欄・編集者さん用の黄色い列はそのまま。

## 画面

### 素材の一覧（場面のカード）

- 各候補画像の下に「💬 コメント 2（未対応 1）」のボタン。押すとその画像のコメント欄が開く。
- 場面の見出しに未対応の数を表示（橙の印。既存の「要確認」と同じ色の決まり）。
- 絞り込みに **「未対応コメント」** を追加（すべて／未採用／採用済み／要修正／未対応コメント）。
- 一覧の上の集計に「未対応コメント N 件」を追加。

### 大きく比較・採用（比較ダイアログ）

- 画像の下に、表示中の候補のコメント欄を置く（PCは右の候補の下、スマホは画像の直後）。
- 「前の場面／次の場面」で移動しても、コメント欄はその場面の候補に切り替わる。新居先生はスマホでこの画面を順に送りながら書ける。
- 入力欄は1つ。送信は「コメントする」。Enter だけでは送らない（スマホの改行で誤送信しないため）。

### コメント1件の表示

```
新居 ・ 11/3 14:05                    [対応済みにする]
  左の矢印の向きが逆では？ 円安で輸出は増える方向。
  └ 三上 ・ 11/3 15:20：直しました（候補3）
```

- 名前・日時（日本時間）・本文。返信は1段だけ（返信の返信は作らない）。
- 自分のコメントは「直す」「取り消す」ができる（取り消しは「取り消されたコメント」と残す。完全には消さない）。
- 対応済みは灰色にして畳む。「対応済みも表示」で開く。

### コメントを見ながらやり直す

- 既存の「この画像を直す」「候補を追加」のダイアログに、その場面の**未対応コメントを一覧で表示**し、各コメントに「指示に入れる」ボタンを付ける。押すと指示欄に本文が入る（そのまま生成はしない。作り手が直してから「候補を作る」）。
- 新しい候補ができても、コメントは自動で「対応済み」にしない。作り手が新しい候補を見て自分で閉じる（返信に「候補3で直しました」を自動で添える案内を出す）。
- 有料の生成を自動で走らせる動きは一切入れない。

### 名前の出し方

- サーバーが Cloudflare の証明から本人のメールを確かめ、書いた人として記録する（画面の入力で名前を偽れない）。
- 画面にはメールではなく**表示名**を出す。初めてコメントする時に1回だけ「表示名」（例：新居、三上）を聞き、メールと結びつけてサーバーに保存する。後から変えられる。
- ローカル開発（Cloudflare なし）は「ローカル」と記録する。

## 保存の形

案件ごとに新しいファイル `output/<job>/material_comments.json` を作る。採用の記録（`material_library.json`）とは分ける。コメントが採用の版番号（`selection_revision`）を動かさないため、誰かがコメントしている間に別の人が採用しても衝突しない。

```json
{
  "version": 1,
  "revision": 12,
  "comments": [
    {
      "id": "c_7f3a…",
      "no": "15",
      "candidate_id": "v_ab12…",
      "candidate_sha256": "…",
      "parent_id": null,
      "author_email": "…",
      "author_name": "新居",
      "body": "左の矢印の向きが逆では？",
      "created_at": "2026-11-03T05:05:00+00:00",
      "edited_at": null,
      "status": "open",
      "resolved_by": null,
      "resolved_at": null,
      "withdrawn": false
    }
  ]
}
```

- 表示名の対応表は `/data/material_people.json`（メール→表示名）。Git には入れない。
- 本文は1,000字まで・1案件あたり3,000件まで。画面ではすべて文字として表示（HTMLとして扱わない）。
- 書き込みは既存の `store.LOCK` の中で読み直してから保存（一時ファイル→置き換え）。
- 古い案件はファイルが無い＝コメント0件として読む。**データの移行は不要**で、三上さんの既存の画像にもそのまま書ける。

## API

すべて既存の認証・CSRF・外部サイトからの書き込み拒否をそのまま通す。

| 操作 | 入口 |
|---|---|
| 一覧（案件全体） | `GET /api/material-jobs/<job>/comments`（`?since=<revision>` で差分だけ） |
| 書く・返信 | `POST /api/material-jobs/<job>/comments`（`no`・`candidate_id`・`body`・`parent_id`・操作IDで二重送信を防ぐ） |
| 直す・取り消す | `POST /api/material-jobs/<job>/comments/<id>`（`action=edit/withdraw`。本人だけ） |
| 対応済み・開き直す | `POST /api/material-jobs/<job>/comments/<id>/status`（誰でも可・した人と日時を記録） |
| 表示名 | `GET/POST /api/me/display-name` |

- 画面は開いている間、30秒ごとに差分だけ読み直す（タブが裏にある時は止める。既存の状況表示と同じ決まり）。同時に見ている人のコメントが、再読み込みなしで出てくる。
- 素材の再読み込み（`sync`）・採用・生成の処理には触れない。

## スプシ・CSV・引き継ぎ

- スプシ（Google）とCSVに **「スタジオのコメント」列** を足す（今の「コメント」列の右）。中身はその場面の採用画像（無ければ最新の候補）へのコメントを時系列で、`[未対応] 新居 11/3：…` `[済] 三上 11/3：…` の形。前の候補へのコメントは「（前の候補へ）」と付ける。
- 黄色い「コメント」列は**今までどおり空欄**（編集者さんが書く欄）。
- 書き出しの画面に「スタジオのコメントを含める：未対応だけ／すべて／含めない」を置く。既定は「すべて」（下の「決定事項」②）。
- 採用素材ZIPの書き出しは止めない。未対応のコメントがある時は、書き出しの確認に「未対応のコメントが N 件あります」と出す。
- 引き継ぎJSON（`material-handoff.json`）には件数だけ（`review_comments: {open, resolved}`）を足し、本文は入れない。`schema_version` は1のまま（項目の追加のみ）。

## 入れないもの（今回）

- 画像の上の位置を指してのコメント（ピン留め）・手書きの印。要望が出たら次の段階で。
- Chatwork への自動通知。まずはツールの中で回し、必要なら「今日のコメントをまとめて知らせる」ボタンを後で検討。
- スプシ上のコメントのツールへの取り込み（今の方針どおり、書き出しは一方向）。
- 旧画面（詳しい進捗・手直し `/progress/<job>`）へのコメント欄。コメントは素材スタジオの画面だけ。
- 担当者ごとの権限の分け方（今のログインできる人は全員、書く・閉じるができる）。

## 試験と反映

- Python：書く・返信・直す・取り消し・対応済み・開き直し・本人以外の編集拒否・CSRF・外部からの書き込み拒否・二重送信・1,000字超・件数上限・古い案件（ファイル無し）・採用と同時の書き込み・壊れたファイルの読み込み・スプシとCSVの列・数式として解釈されない（`=` 始まり）・引き継ぎJSONの件数。
- Node：コメント欄の描画（HTMLを文字として出す）・差分の読み直し・絞り込み。
- Chrome：390px幅（スマホ）と PC で、比較ダイアログを送りながら書く・別のタブで書いたコメントが30秒以内に出る・「指示に入れる」・書き出しの列。合成データで行い、画像生成は呼ばない。
- 本番前の検査 `scripts/check_production.py` に追加。反映は `DEPLOYMENT.md` の生成保護（生成中は待つ）に従う。
- 本番での確認は**読み取りだけ**（稼働版のコミット・素材画面の表示・コメント一覧の取得が200で0件または既存件数）。本番の案件に試しのコメントを書かない（取り消しても「取り消されたコメント」がスタッフに見えるため）。書き込みの動きは手元の合成データで確かめる。

## 決定事項（2026-11-03 社長承認）

1. **この形で作る**（コメントは画像に付ける・要修正メモとは別・対応済みで閉じる）。
2. **スプシに入れるコメントの既定は「すべて（済も含む）」**。編集者さんがやり直しの経緯を見られ、要らなければ列を隠せるため。書き出しの画面で「未対応だけ／含めない」も選べる。
3. **表示名は本人が初回に入れる**（名簿の設定は作らない）。

### 社長からの追加依頼「UIデザインもブラッシュアップしてね」（2026-11-03）

「画像を順に見る」と各候補の「コメント」から同じ確認画面に入る。スマホは画像の下、PCは画像の右に会話を表示する。場面送りを下端に固定し、未対応や章で絞って開いた場合はその時点の画像がある場面をたどる。自分の投稿の編集・取り消しは「•••」にまとめ、返信中は入力欄に相手と本文の抜粋を表示する。「大きく比較・採用」は従来の採用操作に使う。稼働版のSHAと確認結果はAI_Workspaceの元の依頼書に記録する。

社長からの追加依頼で、説明と空欄の案内を外し、会話の前に入力欄と「送信」を並べた。初回は本文を書き始めてから表示名を尋ねる。Enterは改行のまま。原稿は画像の「原稿」で開き、候補の切り替えは複数ある場面だけに出す。返信・編集を取り消したときや送信した後も、先に書いていた新規コメントは残す。
